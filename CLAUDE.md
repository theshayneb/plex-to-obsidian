# Media Manager: notes for Claude Code

A personal Obsidian plugin, "Media Manager" (formerly Media Import and Sync; id `plex-media-notes`, kept so the installed folder and settings survive; don't change it) that creates and syncs notes for Plex movies, TV shows, documentaries and music tracks, and Steam games. The owner is the only user.

## Workflow

- Push finished, checked work straight to `main`. No pull requests, no asking first.
- Every change that ships gets a new patch version (0.0.x) and a GitHub release:
  1. Bump the version in `manifest.json`, `package.json` and `package-lock.json` (the top-level `version` and `packages[""].version`), and add it to the top of `versions.json` mapped to `manifest.json`'s `minAppVersion`.
  2. Add a `## [x.y.z] - YYYY-MM-DD` entry at the top of `CHANGELOG.md`. The release workflow uses it as the release notes and fails without it.
  3. Commit and push to `main`, then publish the release with `.github/workflows/release.yml`, which builds the plugin and attaches `main.js`, `manifest.json` and `styles.css`. Either push the tag `x.y.z` (no `v` prefix) pointing at that commit, or, where tag pushes are blocked (cloud sessions), run the "Release Plugin" workflow on `main` with the input `version: x.y.z`; it creates the tag itself.
  4. Tell the owner the version number. Don't give them git commands; they use the GitHub web interface.
- Never reuse a version number that was already tagged or released.

## Checks before pushing

```
npm run lint   # eslint + tsc
npm test
npm run build
```

## Things to know

- `src/config.ts` (settings shape, per-library defaults, migration from older saved settings), `src/notes.ts` (matching, file names, classification) and `src/properties.ts` (the Plex field → property catalogue, `FIELD_SOURCES`) are pure (no Obsidian imports) and unit tested; `src/sync.ts` does the vault work, `src/plex.ts` and `src/steam.ts` the HTTP calls (via `requestUrl`, which avoids CORS); `src/steam-data.ts` (pure, tested) maps Steam's responses. Steam games are items of type `game` with rating key `steam-<appid>`, in the library keyed `steam` (`STEAM_LIBRARY`); their Link is the Steam Store page and their images are linked, not downloaded. Steam's owned-games list leaves out free games never played, so `prepare` also adds every game a note links to (`steam-<appid>` in the game index) that the list lacks, named as its note (so never renamed for it), with no playtime and no Store request (details come through `fullItem` only when a check or fill-in needs them). The Steam Store's appdetails is rate limited (about 200 per 5 minutes), hence `SteamClient.storeGapMs`. HowLongToBeat (`src/hltb.ts`, pure parts in `src/hltb-data.ts`) has no public API: it mimics the site's search (GET `/api/search/site/init` for a token tied to IP and user agent, then POST `/api/search/site` with `x-auth-token`), needs a `Referer` header (falls back to Node's https on desktop if Obsidian drops it), and only accepts exact-name matches. If it breaks, re-read the site's search code (`/_next/static/chunks/*.js`, look for `/api/search`). SteamGridDB (`src/steamgriddb.ts`) needs the user's key and only offers covers in the pop-up.
- "Add something new" (`src/add-modal.ts`, `src/discover.ts`, pure mapping in `src/discover-data.ts`) searches OMDb (movies/shows, key in `settings.omdbKey`), the Steam Store and HowLongToBeat (games) and Open Library (books), and makes one note through `PlexSync.addNew` (same approval and properties as a sync). Items found this way have keys `imdb-…`, `steam-…`, `hltb-…`, `ol-…`, a `webLink` used as their Link, and linked (not downloaded) covers. Plex items also match notes linked to their IMDb ID (`itemKeys`; listings use `includeGuids=1`). Books live in the library keyed `books` (`BOOKS_LIBRARY`), which no sync reads. A book's summary comes from Google Books (`googleBooksInfo`: by ISBN, then title and author, only accepting a same-titled result via `googleDescription`; optional `settings.googleBooksKey`), falling back to Open Library's description, and so does the day and month of its date (`googleDate`, only within the first-publication year); everything else about books is Open Library's. A book's year is `firstPublishYear` (Open Library's earliest edition year only when other editions bear it out) and the earliest across every same-titled record by the same author (`sameBooks`, `earliestYear`; the record with most editions is the one picked by title). A book's "Fiction" genre is dropped when it has another kept genre (`fictionOnlyAlone`). The OMDb and Open Library code follows Media DB Mod's (theshayneb/media-db-mod), which the owner used before.
- Folder, file name, matching, properties and property values are per library (`LibrarySetting`); character replacements, images subfolder and renaming are plugin-wide (documentaries are only what is in a library set to Documentaries; there is no genre detection). Changing settings shape needs a migration in `loadSettings`. Music libraries make one note per track and start as skipped.
- Release dates are always full YYYY-MM-DD (`fullDate`: a year alone becomes YYYY-01-01, also when a source has only a year), since Obsidian can't read year-only dates. A check never makes a date vaguer (a year-only source date leaves a full date from the same year alone, and starts unticked against any date of the owner's). In a check, a note's year-only date (`vagueDate`, also YYYY-01-01) gives way, ticked, to the source's date from the same year; the command "Check notes with a year-only date against sources" (`vagueDateNotes`) checks only those notes' dates.
- Music notes don't record a track's length (no Duration). A book's page count goes in Duration. One-time changes to saved settings go through `migrateOnce` (names kept in `settings.migrations`), so the owner can undo them by hand.
- Properties are user-configurable. The video defaults in `DEFAULT_PROPERTIES` (Genre, Summary, Date, Duration, Status, Link, Image, tags) are the owner's choice; don't rename them. To offer a new Plex field, add it to `FieldSource`, `FIELD_SOURCES` and `sourceValue`.
- Documentaries never list "Documentary" as a genre. Genres are limited to `settings.allowedGenres` ("Genres to keep", `keepGenres` with `GENRE_ALIASES`; empty keeps all), passed in `NoteContext.genres`; a library's `leaveOutGenres` ("Genres to leave out", `NoteContext.leaveOut`) are dropped after that (music leaves out Romance). A game's Steam store tags (`steamTags`, from `IStoreBrowseService/GetItems` with tag names from `IStoreService/GetTagList`) are added to its genres only when a keep list is set, so only kept tags show.
- Existing notes: the only changes allowed are renaming them to their library's file name format (`renameExistingNotes`, via `fileManager.renameFile`, in place) and adding properties marked `fill` when they're missing or empty (never overwriting), and overwriting `PLAY_SOURCES` properties (Play count, game playtime; a playtime only ever upwards, `playtimeShrinks`, in syncs and checks) with `updatePlayCounts` on and `RATING_SOURCES` properties (Your rating) with `updateRatings` on (never clearing one Plex has no value for), and `STATUS_SOURCES` properties with `updateStatus` on, only forward (`statusMovesForward`: not watched → started → watched, from empty, never from a status of the owner's own), and replacing a link property that doesn't point to the item (`planLinks`; only in full syncs with asking on, offered ticked for search pages (`isSearchLink`) and unticked otherwise; one left unticked is remembered in `settings.keptLinks` and not offered again), and correcting a `CHECKED_SOURCES` property (Duration in minutes) whose value differs from the source's (`planChecks`; same conditions, ticked when `sameLengthOtherForm` says it's the same length in hours or text, unticked otherwise, kept ones remembered in `settings.keptValues`), and, only through the "Check existing notes against sources" command (`CheckModal` picks the properties, remembered in `settings.checkProperties`; `run(…, 'check', names)` always asks, fetches each item's full details and does nothing else), replacing any chosen property (every source is compared; `UNCHECKED_SOURCES` is empty) where `checkValue`/`compareNote` find a difference (`planFullCheck`; missing or empty values, hours-durations, search links, genres (the note's kept genres plus the source's) and the source's tag added to the note's tags ticked; a status ticked only when `statusMovesForward`, never for books; a rating of the owner's offered both ways, both unticked (the note's line to Plex's value, and a `plexRating` line sending the note's to Plex); a Plex poster only for an empty image property, downloaded on approval; other differences unticked; kept ones in `settings.keptValues`); for the Books library, `checkBooks` uses each note's Open Library work (`lookUpBook`), found by title and author when it has no Open Library link, which it then also offers (a link left unticked is remembered as `keptLinks['book:<path>']` and that note isn't looked up again); notes nothing matched are listed, all only when `planRenames` says the match is unambiguous. Matching uses the Plex rating key inside the Plex link property (plus `Link`), then file names as the library's `matchBy` allows; songs are also matched under each of their artists alone, the title's featured ones included, and without featured artists (`artistsOf`, `withoutFeatured` in `candidateNames`; `songNameVariants`, which reads a music note's name with its library's file name format, for music notes' names in the index). A note whose Plex links (plain numeric keys) all point to nothing `prepare` listed (an album link, a re-added track) isn't tied to them (`keysByPath` entry dropped), so it's matched by name again.
- Offered replacements of values already in a note start ticked when `settings.tickDifferences` is on (default); off, only clear-cut fixes do (the heuristics above). An image property holding a `[[…]]` link to a vault file is the owner's own pick: in a check it's always offered unticked (`Checks.yours`).
- "Apply/Create all the rest" (`approvedAll`) only covers the rest of that run and that action; it leaves out what was unticked when it was pressed and every line that starts unticked in the notes it skips showing.
- With `askBeforeChanges` on, every creation and every change to an existing note goes through `PlexSync.ask` (the approval pop-up) first, with nothing written (not even a poster or folder) before approval. New writes must be planned, shown (one `ApprovalLine` per part, which can be unticked), then applied without the unticked parts and with the pop-up's edits (`Decision.edits`, turned back into values by `parseEdit`).
- "Use an existing note" (choice `merge` in the create pop-up, `NotePickerModal`) ties an item to a note the user picks: `settings.merged` (rating key → path, kept current on vault renames in `main.ts`) puts it in the index (`addMerged`) so it's matched there from then on and never renamed; the pick also offers to fill in every property the note is missing or has empty, never overwriting.
- Full syncs and checks list the notes in active libraries' folders that no item matches (`listUnmatched`, `result.unmatched`), each explained where its link allows (`explainUnmatched`, using `explainMissing`; `result.unmatchedWhy`), shown in `UnmatchedModal` with Open and "Always ignore" (`settings.unmatchedIgnored`, paths kept current on vault renames, undone in Settings → Skipped every time).
- Items in `settings.ignored` ("Skip every time", keyed by rating key) are never created or changed by any sync, but still take part in matching (`planRenames`) so their notes aren't claimed by other items.
- A note whose name matches several items (`ambiguousNotes`) is resolved by asking (`OwnerChooser`, full syncs with asking on): the chosen item is tied to it in the index, the rest stop matching it. `PlexSync.explain` reports, without writing, what a sync does with an item; keep it in step with `run`.
- `run(…, 'check', names, only)` checks just the notes in `only` ("Check this note against sources" passes the open note and every property); `result.checked` lists the notes compared.
- A check converts ratings (`planRescale`) and offers sending them to Plex only when a rating property is among those checked. (The per-property "Check one property: <name>" commands were removed at the owner's request in 0.0.83; the `CheckModal` covers it.)
- Change pop-ups show the whole note: `PlexSync.ask` adds `ApprovalRequest.unchanged` (the file name, unless a rename line shows it, and every other frontmatter property no line is about), listed after the lines, with a warning (`warn`) on number properties (`NUMBER_SOURCES`: minutes, pages) holding text; changed property names are bold in the accent colour (`pmn-approval-changed`). `FILE_NAME` ("File name", `check-modal.ts`) is a checkable pseudo-property: a check with it offers renaming to the library's format (not for books or notes tied with "Use an existing note").
- Existing-note pop-ups (full syncs and checks; not books) are planned first and asked afterwards (`pending` in `run`, each with a `decide` closure), sorted by library (settings order), then by the set of line labels (fewest first, then alphabetically); `ApprovalRequest.group` names the group and the place in it; "Apply to the rest of this group" (choice `group`, `groupKey`/`groupLeft`, remembered in `approvedGroups`) works like "all the rest" within one group.
- Every row of a change pop-up is editable: the `unchanged` rows (`UnchangedLine`, keys `own:<name>` and `own-file`) come back in `Decision.edits` and are written by `PlexSync.applyOwnEdits` right after approval (apply or all; never repeated by "all the rest"), before the callers' own changes.
- A song's Plex link is its album's page plus `&track=<key>` (`plexWebLink` with an album key; `ratingKeyFromLink` reads `track=` first), since Plex Web has no track pages; a check of the link property offers to replace an older track link, ticked.
- Playlists: the "Plex playlist" Bases view (`src/playlist-view.ts`, registered only when `registerBasesView` exists, so `BasesView` is only touched on Obsidian 1.10+) sends a Base's notes, in its order, to Plex as a music playlist (`planPlaylist`/`sendPlaylist` in `src/playlist.ts`: each note's Plex link or merged item, songs only, after a confirming pop-up; a same-named playlist is emptied and refilled, a smart one refused). This and ratings are the only things the plugin writes outside the vault.
- Ratings go both ways: `settings.ratingsSeen` keeps the rating a note and Plex last agreed on, and `ratingDirection` decides which side changed (`ratingPlan`); Plex→note needs `updateRatings` and never overwrites a rating changed in the note; note→Plex (`sendRatings`, `PlexClient.rate`, level × 2) is only ever offered in the approval pop-up of a full sync or a check; the level sent is `plexRatingToSend`'s (the Plex line as edited, else the note's converted rating as edited, else the offer). Ratings and playlists are the only things the plugin writes outside the vault.
- Steam collections (`steamCollections` source) come from the Steam client's local cloud storage file (`userdata/<account id>/config/cloudstorage/cloud-storage-namespace-1.json`, parsed by `collectionsByGame`; read by `readSteamCollections` in `src/steam-local.ts` through Node's fs, desktop only, in `settings.steam.folder` or the usual places). Hidden and dynamic collections are left out. `MIRRORED_SOURCES` are updated on every sync (and in the background) whenever they can be read; where they can't (phones), the property is left alone. Writing collections back to Steam was ruled out (it needs the owner's login session and can wipe collections).
- The owner's rating scale (`RatingScale` 'stars', the "Your rating (💣 ⭐ 🩷)" source): one per Plex star, 💣 ⭐⭐ ⭐⭐⭐ ⭐⭐⭐⭐ 🩷, empty for none, in every library (`starEmoji`; Plex's 0–10 is levels × 2). Notes written before it used 'emoji' (💣 ⭐ ⭐⭐ ⭐⭐⭐ 🩷 for Plex's pairs) or, for music, 'plain' (⭐ to ⭐⭐⭐⭐⭐); `noteStars` reads a note in the scale `noteScale` gives it, the old one until `settings.ratingsReviewed` has its rating key. Every pop-up for a note not yet reviewed (syncs with asking on, checks, "Use an existing note") offers its rating in the star scale (`planRescale`/`planRescaleOf`, `rescaleLines`, `applyRescale`; editable); answering marks it reviewed either way. Book notes (keyed `book:<path>`, old scale 'emoji', any property named like a library's emoji rating property) get it in the check, found on Open Library or not. Notes the plugin creates are reviewed from the start.
- Music file tags (source `fileTag`, the tag's name in `PropertyMapping.text`, passed to `sourceValue` everywhere): `prepare` reads each track's file (the listing's `Media[0].Part[0].file`; Obsidian runs on the Plex machine) with `readFileTags` (`src/music-files.ts`, desktop only, Node fs, only the ID3 tag at the start), parsed by the pure, tested `readId3`/`tagValue` (`src/id3.ts`: ID3v2.2–2.4, standard frames by ID, the owner's own TXXX tags by name, friendly names like Tempo), into `PlexItem.fileTags`; only for music libraries using the source, and not for 'playCounts' runs, recommendations or explain. Files are never written. Lyrics (source `lyricsFile`, `PlexItem.lyrics`) come the same way from the text file beside the music file (`readLyrics`: same name with .txt or .lrc, decoded by `decodeText`, Windows line endings made plain, otherwise exactly as written).
- A track's own moods aren't in library listings, so `fullItem` fetches the track when its library uses the moods source.
- The background schedule (`playCountHours`) runs `PlexSync.run(…, 'playCounts')`, which must only ever touch play counts, ratings and statuses (each only when its setting is on) and Steam collections.
- Never put the Plex token in note content (Plex image URLs need it, which is why posters are downloaded, into `<media folder>/Images`).
- Styles live in `styles.css`, with classes prefixed `pmn-`; use Obsidian's CSS variables, not inline styles.
- Commands (ids unchanged, so hotkeys survive): "Sync with Plex and Steam" (`create-notes-from-plex`), "Check notes against sources…" (`check-notes`, the `CheckModal`), "Check this note", "Fix year-only dates", "Add a movie, show, game or book…" (`add-new`), "Why isn't this imported?…" (`explain-item`), "Tie this note to a Plex item…" (`tie-note`, `TieModal` in `src/tie-modal.ts`: a pasted Plex link, an album's listing its tracks via `PlexClient.children` to pick from, written to `settings.merged` like "Use an existing note", replacing an earlier tie of that note). Older notes here may use the old names (Import and sync, Check existing notes against sources, Add something new, Explain why…). Settings sections: Connections, Syncing, New notes, Libraries, Remembered choices (merged notes, skipped items, ignored unmatched notes, kept values and links).
- Recommendations (stage 1, own library only): the dashboard view `RecommendView` (`src/recommend-view.ts`, view type `pmn-recommendations`, "Open recommendations") reads every note in the libraries' folders (`noteEntries` in `src/recommend-data.ts`: rating in the note's scale, unseen = status equals the library's not-watched value, genres/styles/moods and people from the libraries' properties) plus Plex/Steam items (`PlexSync.libraryItems`: items with one note, by path, have their genres and people added to that note's entry by `withItem`, for ranking only, so notes needn't hold directors or cast; items without notes are candidates via `itemEntry`; a book's author also comes from a "Title by Author" file name), and ranks with the pure `recommend` (`src/recommend.ts`, tested): loved = level ≥ 4 (🩷 counts double), open = no rating or unseen, within one `RecGroup` (video/music/game/book); a shared person counts 3, genres by scaled overlap. "Not interested" goes in `settings.notInterested` (`note:<path>` / `item:<key>`); "Make a note" uses `addNew`, which connects to Plex for Plex items. Stage 2 (TMDB, Last.fm, IGDB, or an AI service) is still to be decided by the owner.
- UI text must be sentence case (Obsidian lint rule); brand words are allowed in `eslint.config.mjs`.
