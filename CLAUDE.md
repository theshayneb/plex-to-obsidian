# Media Manager: notes for Claude Code

A personal Obsidian plugin, "Media Manager" (formerly Media Import and Sync; id `plex-media-notes`, kept so the installed folder and settings survive; don't change it) that creates and syncs notes for Plex movies, TV shows, documentaries and music tracks, and Steam games. The owner is the only user.

## Workflow

- Push finished, checked work straight to `main`. No pull requests, no asking first.
- Every change that ships gets a new patch version (0.0.x) and a GitHub release:
  1. Bump the version in `manifest.json`, `package.json` and `package-lock.json` (the top-level `version` and `packages[""].version`), and add it to the top of `versions.json` mapped to `manifest.json`'s `minAppVersion`.
  2. Add a `## [x.y.z] - YYYY-MM-DD` entry at the top of `CHANGELOG.md`. The release workflow uses it as the release notes and fails without it.
  3. Commit and push to `main`, then publish the release with `.github/workflows/release.yml`, which builds the plugin and attaches `main.js`, `manifest.json` and `styles.css`. Either push the tag `x.y.z` (no `v` prefix) pointing at that commit, or, where tag pushes are blocked (cloud sessions), run the "Release Plugin" workflow on `main` with the input `version: x.y.z`; it creates the tag itself.
  4. Tell the owner the version number. Don't give them git commands; they use the GitHub web interface.
- Never reuse a version number that was already tagged or released.

## Checks before pushing

```
npm run lint   # eslint + tsc
npm test
npm run build
```

## Things to know

- `src/config.ts` (settings shape, per-library defaults, migration from older saved settings), `src/notes.ts` (matching, file names, classification) and `src/properties.ts` (the Plex field → property catalogue, `FIELD_SOURCES`) are pure (no Obsidian imports) and unit tested; `src/sync.ts` does the vault work, `src/plex.ts` and `src/steam.ts` the HTTP calls (via `requestUrl`, which avoids CORS); `src/steam-data.ts` (pure, tested) maps Steam's responses. Steam games are items of type `game` with rating key `steam-<appid>`, in the library keyed `steam` (`STEAM_LIBRARY`); their Link is the Steam Store page and their images are linked, not downloaded. Steam's owned-games list leaves out free games never played, so `prepare` also adds every game a note links to (`steam-<appid>` in the game index) that the list lacks, named as its note (so never renamed for it), with no playtime and no Store request (details come through `fullItem` only when a check or fill-in needs them). The Steam Store's appdetails is rate limited (about 200 per 5 minutes), hence `SteamClient.storeGapMs`. HowLongToBeat (`src/hltb.ts`, pure parts in `src/hltb-data.ts`) has no public API: it mimics the site's search (GET `/api/search/site/init` for a token tied to IP and user agent, then POST `/api/search/site` with `x-auth-token`), needs a `Referer` header (falls back to Node's https on desktop if Obsidian drops it), and only accepts exact-name matches (`HltbClient.times` tries each of `titleVariants`: the name, then without a subtitle or edition). If it breaks, re-read the site's search code (`/_next/static/chunks/*.js`, look for `/api/search`). SteamGridDB (`src/steamgriddb.ts`) needs the user's key and only offers covers in the pop-up.
- "Add something new" (`src/add-modal.ts`, `src/discover.ts`, pure mapping in `src/discover-data.ts`) searches OMDb (movies/shows, key in `settings.omdbKey`), the Steam Store and HowLongToBeat (games) and Open Library (books), and makes one note through `PlexSync.addNew` (same approval and properties as a sync). It starts on Book. Each result shows its ratings (`Found.ratings`: Open Library's and Google Books' star averages, Steam search's Metacritic score, HowLongToBeat's review score), plus, asked for once the results show (`moreRatings`), OMDb's IMDb, Rotten Tomatoes and Metacritic for movies and shows (`omdbRatings`; the details are kept, `omdbDetailsOf`, and reused if it's picked) and Steam's player reviews (`appreviews`, `steamReviews`). Items found this way have keys `imdb-…`, `steam-…`, `hltb-…`, `ol-…`, a `webLink` used as their Link, and linked (not downloaded) covers. Plex items also match notes linked to their IMDb ID (`itemKeys`; listings use `includeGuids=1`). Books live in the library keyed `books` (`BOOKS_LIBRARY`), which no sync reads. A book's summary comes from Google Books (`googleBooksInfo`: by ISBN, then title and author, only accepting a same-titled result via `googleDescription`; optional `settings.googleBooksKey`), falling back to Open Library's description, and so does the day and month of its date (`googleDate`, only within the first-publication year); everything else about books is Open Library's, found by `lookUpBook`'s `openLibraryByName` (the title-and-author search; when it finds nothing, a plain `q=` search for both, whose same title counts even with the author spelled differently, then the title alone), also first for a note linked to Google Books (only the same title by the same author; its Open Library link is then offered like a searched book's, `searched`, and a refusal kept in `keptLinks['book:<path>']` stops that), except for books Open Library doesn't have: `lookUpBook` then takes Google Books' same title by the same author (`googleSameBooks`, mapped by `googleFound`: key `gb-<volume id>`, link `books.google.com/books?id=…`, which `ratingKeyFromLink` reads and `checkBooks` looks up directly as `volume`; `googleVolumes` throws on 429/503 so a busy Google Books is a failure, not "not found", with Google's reason via `googleRefusal`, prefixed with what Open Library was asked for). `googleBooksGet` caches 200 answers while Obsidian runs, retries 429/503 after 2, 6 and 15 s, and after a "per day" quota refusal answers 429 without asking for an hour (`googleOut`, for that key only, `keyIn`, so a newly entered key is asked at once; the Test button passes `fresh`); the refusal message says how many requests went to Google Books since Obsidian started (`googleAsked`). `checkBooks` only asks Google Books for summaries and dates (`lookUpBook`'s `googleInfo`) when a summary or release date property is checked. `checkBooks` reads a "Title by Author" file name as title and author even without an author property, then tries the whole name (a year in brackets at the end, "Title (2017)", left out of both), and `findItems('book')` lists Google Books results after Open Library's (same title and author once, `bookKey`). A book's year is `firstPublishYear` (Open Library's earliest edition year only when other editions bear it out) and the earliest across every same-titled record by the same author (`sameBooks`, `earliestYear`; the record with most editions is the one picked by title). A book's "Fiction" genre is dropped when it has another kept genre (`fictionOnlyAlone`). Open Library requests go through `openLibraryJson` (answers kept while Obsidian runs, up to 3000; started 350 ms apart, 1100 ms for good after a 429/5xx, which is retried after 3 and 10 s; `resetOpenLibrary` for tests); `lookUpBook` asks a linked work's search entry, page and same-titled records at once, and `checkBooks` looks books up three at a time (`limited(3)`, the `ahead` map) before its loop. The OMDb and Open Library code follows Media DB Mod's (theshayneb/media-db-mod), which the owner used before.
- Folder, file name, matching, properties and property values are per library (`LibrarySetting`); character replacements, images subfolder and renaming are plugin-wide (documentaries are only what is in a library set to Documentaries; there is no genre detection). Changing settings shape needs a migration in `loadSettings`. Music libraries make one note per track and start as skipped.
- Release dates are always full YYYY-MM-DD (`fullDate`: a year alone becomes YYYY-01-01, also when a source has only a year), since Obsidian can't read year-only dates. A check never makes a date vaguer (a year-only source date leaves a full date from the same year alone); a date from another year is offered like any difference (ticked with `tickDifferences`), books included. In a check, a note's year-only date (`vagueDate`, also YYYY-01-01) gives way, ticked, to the source's date from the same year; the command "Check notes with a year-only date against sources" (`vagueDateNotes`) checks only those notes' dates.
- A game's length (`LENGTH_SOURCES`: durationMinutes/Text/Clock, via `lengthOf`) is HowLongToBeat's main story (minutes; `hltbTimes` falls back to main + extras, `comp_plus`, when there's no main story time, for Main Story too), which `gameDetails` looks up when the library uses any of them. In a check, a `CLEARABLE_SOURCES` property (lengths, `hltbMain`, pages) the source has no value for but the note does is offered as empty, unticked (`yours`).
- Music notes don't record a track's length (no Duration). A book's page count goes in Duration. One-time changes to saved settings go through `migrateOnce` (names kept in `settings.migrations`), so the owner can undo them by hand.
- Properties are user-configurable. The video defaults in `DEFAULT_PROPERTIES` (Genre, Summary, Date, Duration, Status, Link, Image, tags) are the owner's choice; don't rename them. To offer a new Plex field, add it to `FieldSource`, `FIELD_SOURCES` and `sourceValue`.
- Documentaries never list "Documentary" as a genre. Genres are limited to `settings.allowedGenres` ("Genres to keep", `keepGenres` with `GENRE_ALIASES`; empty keeps all), passed in `NoteContext.genres`; a library's `leaveOutGenres` ("Genres to leave out", `NoteContext.leaveOut`) are dropped after that (music leaves out Romance). A game's Steam store tags (`steamTags`, from `IStoreBrowseService/GetItems` with tag names from `IStoreService/GetTagList`) are added to its genres only when a keep list is set, so only kept tags show.
- Existing notes: the only changes allowed are renaming them to their library's file name format (`renameExistingNotes`, via `fileManager.renameFile`, in place) and adding properties marked `fill` when they're missing or empty (never overwriting), and overwriting `PLAY_SOURCES` properties (Play count, game playtime; a playtime only ever upwards, `playtimeShrinks`, in syncs and checks) with `updatePlayCounts` on and `RATING_SOURCES` properties (Your rating) with `updateRatings` on (never clearing one Plex has no value for), and `STATUS_SOURCES` properties with `updateStatus` on, only forward (`statusMovesForward`: not watched → started → watched, from empty, never from a status of the owner's own), and replacing a link property that doesn't point to the item (`planLinks`; only in full syncs with asking on, offered ticked for search pages (`isSearchLink`) and unticked otherwise; one left unticked is remembered in `settings.keptLinks` and not offered again), and correcting a `CHECKED_SOURCES` property (Duration in minutes) whose value differs from the source's (`planChecks`; same conditions, ticked when `sameLengthOtherForm` says it's the same length in hours or text, unticked otherwise, kept ones remembered in `settings.keptValues`), and, only through the "Check existing notes against sources" command (`CheckModal` picks the properties, remembered in `settings.checkProperties`; `run(…, 'check', names)` always asks, fetches each item's full details and does nothing else), replacing any chosen property (every source is compared; `UNCHECKED_SOURCES` is empty) where `checkValue`/`compareNote` find a difference (`planFullCheck`; missing or empty values, hours-durations, search links, genres (the note's kept genres plus the source's) and the source's tag added to the note's tags ticked; a status ticked only when `statusMovesForward`, never for books; a rating of the owner's offered both ways, both unticked (the note's line to Plex's value, and a `plexRating` line sending the note's to Plex); a Plex poster only for an empty image property, downloaded on approval; other differences unticked; kept ones in `settings.keptValues`); for the Books library, `checkBooks` uses each note's Open Library work (`lookUpBook`), found by title and author when it has no Open Library link, which it then also offers (a link left unticked is remembered as `keptLinks['book:<path>']` and that note isn't looked up again); notes nothing matched are listed, all only when `planRenames` says the match is unambiguous. Matching uses the Plex rating key inside the Plex link property (plus `Link`), then file names as the library's `matchBy` allows; songs are also matched under each of their artists alone, the title's featured ones included, and without featured artists (`artistsOf`, `withoutFeatured` in `candidateNames`; `songNameVariants`, which reads a music note's name with its library's file name format, for music notes' names in the index). A note whose Plex links (plain numeric keys) all point to nothing `prepare` listed (an album link, a re-added track) isn't tied to them (`keysByPath` entry dropped), so it's matched by name again.
- Kept values (`settings.keptValues`) are written by `PlexSync.keep` as JSON `{kept, offered}` and read by `isKept`: kept only while the note's value and the source's offer are both unchanged (older plain-string entries match the note's value alone). `migrateOnce('forget-kept-book-dates')` dropped book date/year keeps from before the date fixes. The `plexRating` keep is separate (the note's rating sent).
- Offered replacements of values already in a note start ticked when `settings.tickDifferences` is on (default); off, only clear-cut fixes do (the heuristics above). An image property (`IMAGE_SOURCES`: poster, wideImage) holding a `[[…]]` or `![[…]]` link to a vault file (`isOwnImage`, also a list's first entry) is the owner's own pick: a check never offers to replace it at all (skipped in `compareNote`; before 0.0.158 it was offered unticked).
- "Apply/Create all the rest" (`approvedAll`) only covers the rest of that run and that action; it leaves out what was unticked when it was pressed and every line that starts unticked in the notes it skips showing.
- With `askBeforeChanges` on, every creation and every change to an existing note goes through `PlexSync.ask` (the approval pop-up) first, with nothing written (not even a poster or folder) before approval. New writes must be planned, shown (one `ApprovalLine` per part, which can be unticked), then applied without the unticked parts and with the pop-up's edits (`Decision.edits`, turned back into values by `parseEdit`).
- "Use an existing note" (choice `merge` in the create pop-up, `NotePickerModal`) ties an item to a note the user picks: `settings.merged` (rating key → path, kept current on vault renames in `main.ts`) puts it in the index (`addMerged`) so it's matched there from then on and never renamed; the pick also offers to fill in every property the note is missing or has empty, never overwriting.
- Full syncs and checks list the notes in active libraries' folders that no item matches (`listUnmatched`, `result.unmatched`), each explained where its link allows (`explainUnmatched`, using `explainMissing`; `result.unmatchedWhy`), shown in `UnmatchedModal` with Open and "Always ignore" (`settings.unmatchedIgnored`, paths kept current on vault renames, undone in Settings → Remembered choices).
- Items in `settings.ignored` ("Skip every time", keyed by rating key) are never created or changed by any sync, but still take part in matching (`planRenames`) so their notes aren't claimed by other items.
- A note whose name matches several items (`ambiguousNotes`) is resolved by asking (`OwnerChooser`, full syncs with asking on): the chosen item is tied to it in the index, the rest stop matching it. `PlexSync.explain` reports, without writing, what a sync does with an item; keep it in step with `run`.
- `CheckModal` lists each library (switch remembered in `settings.checkLibraries`, settings keys) with its own properties (`libraryCheckables`: alphabetical, File name first, books also get other libraries' emoji rating names; collapsed, remembered per library in `settings.checkByLibrary`, starting from `checkProperties`) and passes `run` a record of library key → names (`chosenOf(lib)` in `run`; a plain list, as "Check this note" and "Fix year-only dates" pass, applies to every library); `run(…, 'check', names, only, libraries)` sets `onlyLibraries`, which limits `prepare`'s active libraries (others aren't listed at all) and skips `checkBooks` unless `books` is chosen.
- Syncs can be limited too: "Sync with Plex and Steam…" (`create-notes-from-plex`, and the ribbon) opens `SyncModal` (in `check-modal.ts`; libraries remembered in `settings.syncLibraries`; Books never listed) and calls `syncFromPlex(libraries)` → `run(…, 'full', [], undefined, libraries)`, which sets `onlyLibraries` like a check; "Sync every library with Plex and Steam" (`sync-all-libraries`) asks nothing. `listUnmatched` skips folders a left-out library also uses.
- `run(…, 'check', names, only)` checks just the notes in `only` ("Check this note against sources" passes the open note and every property, and, as `libraries`, only the libraries whose folder holds it, so a book note reads no Plex or Steam listing; `checkBooks` looks up only the notes in `only`, tested); `result.checked` lists the notes compared.
- A check converts ratings (`planRescale`) and offers sending them to Plex only when a rating property is among those checked. (The per-property "Check one property: <name>" commands were removed at the owner's request in 0.0.83; the `CheckModal` covers it.)
- Change pop-ups show the whole note: `PlexSync.ask` adds `ApprovalRequest.unchanged` (the file name, unless a rename line shows it, and every other frontmatter property no line is about), listed after the lines, with a warning (`warn`) on number properties (`NUMBER_SOURCES`: minutes, pages) holding text; changed property names are bold in the accent colour (`pmn-approval-changed`). `FILE_NAME` ("File name", `check-modal.ts`) is a checkable pseudo-property: a check with it offers renaming to the library's format (not for notes tied with "Use an existing note"; books too, in `checkBooks`, through `bookForName`: the title as the note's name has it, its capitals kept, the note's author else the book's, the book's year else the name's). Books' default format is "{{title}} by {{author}} ({{year}})", the owner's (`migrateOnce('book-names-by-author')` moved a saved Books library still on "{{title}} ({{year}})", and `migrateOnce('book-names-by-author-always')` any format without `{{author}}`, also putting File name in the Books check's remembered choice); `renderFileName` drops a "by" left with no author. Since 0.0.162 book notes are renamed even when nothing is found (`ownBook`: the name's title and "by" author, the note's author, the year in its name or its date or year property; listed as unmatched too), and every full sync with `renameExistingNotes` on renames them from what they say, looking nothing up (`checkBooks(…, lookUp = false)` after the other libraries, whatever `onlyLibraries` says; only when the note says who wrote it or when). `bookForName` keeps the whole name as the title when its "by" part isn't the author ("Stand by Me" by Stephen King). Book notes are remembered by path (`book:<path>` in `keptLinks`, `keptValues`, `ignored`, `ratingsReviewed`; `reviewSkipped`; `note:<path>` in `notInterested`), all moved on vault renames in `main.ts`.
- Existing-note pop-ups (full syncs and checks; books too, in `checkBooks`, after every lookup) are planned first and asked afterwards (`pending` in `run`, each with a `decide` closure), sorted by library (settings order), then by the set of line labels (fewest first, then alphabetically); `ApprovalRequest.group` names the group and the place in it; "Apply to the rest of this group" (choice `group`, `groupKey`/`groupLeft`, remembered in `approvedGroups`) works like "all the rest" within one group.
- Every pop-up line says where its value comes from and, in change pop-ups, where it's written (`ApprovalLine.source`/`writesTo`, filled in by `PlexSync.withSources` in `ask` from the line's key and its property's source: "Plex", "Steam", "Open Library", "Music file", "Last.fm", "This note"…; written to "This note", "Plex", "Music file", "Lyrics file"; shown as "From: …" under the new value and "Writes to: …" under the name, `pmn-approval-where`). Lines offering the same property from different sources share its name as label (the play count's `count:plex:`/`count:lastfm:` lines are both "Progress"); since 0.0.160 the pop-up shows them as one row with a column per source (Current, then Plex first, then the others by name; each column headed by its source with its own tick box, `pmn-approval-source`, ticking one unticks the rest; the table gets `pmn-approval-cols-N` and other rows' New cell spans the columns), plus `ApprovalLine.also`: sources not offered (`planCountChoices`' other count: "Same as now" or "Lower than now: not offered"), shown in their own column untickable (`pmn-approval-also`), and says above the table which properties have several. The table's text is `--font-ui-small`, the "Current" column was "Existing" before 0.0.160, property names are always bold, and unticked values are muted at the same size.
- The pop-up's boxes suggest the values each property (by name, any case) already has in the vault, as Obsidian's properties do (`vaultPropertyValues`, read once per pop-up; `PropertyValueSuggest`/`matchValues` in `src/property-suggest.ts`): a list's add box always; a text value gets a one-line `input` with suggestions (`pmnTextField`) when it and every vault value are short single lines, else the textarea. Links, images, numbers and the file name get none.
- "Never for this note": the lock beside each line of a change pop-up (`Decision.locked`, labels) puts that label in `settings.lockedProperties[path]` (kept current on vault renames in `main.ts`; listed under Remembered choices → Never changed). `PlexSync.ask` leaves locked lines out unasked in every path (asking off, "all the rest", groups) by adding their keys to `excluded`, and `run` drops notes whose lines are all locked before grouping. Locked keys aren't carried into "all the rest". A new lock is saved (`saveSettings`) as soon as `ask` gets it (`finish` only saves for other changes), and closing the pop-up with × still returns its locks.
- Every row of a change pop-up is editable: the `unchanged` rows (`UnchangedLine`, keys `own:<name>` and `own-file`) come back in `Decision.edits` and are written by `PlexSync.applyOwnEdits` right after approval (apply or all; never repeated by "all the rest"), before the callers' own changes.
- A song's Plex link is its album's page plus `&track=<key>` (`plexWebLink` with an album key; `ratingKeyFromLink` reads `track=` first), since Plex Web has no track pages; a check of the link property offers to replace an older track link, ticked.
- Playlists: the "Plex playlist" Bases view (`src/playlist-view.ts`, registered only when `registerBasesView` exists, so `BasesView` is only touched on Obsidian 1.10+) sends a Base's notes, in its order, to Plex as a music playlist (`planPlaylist`/`sendPlaylist` in `src/playlist.ts`: each note's merged (tied) item, else its Plex link (`songKeyOf`); a link to an album gives the album's track named like the note (`trackForNote`, via `PlexClient.children`); songs only, after a confirming pop-up; a same-named playlist (any case, trimmed) is emptied with `PlexClient.clearPlaylist` (DELETE `/playlists/{id}/items`, then any leftovers one by one) and refilled, and the result's entry count is checked; a smart one refused). This, ratings and music files' own tags and lyrics files (below) are the only things the plugin writes outside the vault.
- Ratings go both ways: `settings.ratingsSeen` keeps the rating a note and Plex last agreed on, and `ratingDirection` decides which side changed (`ratingPlan`); Plex→note needs `updateRatings` and never overwrites a rating changed in the note; note→Plex (`sendRatings`, `PlexClient.rate`, level × 2) is only ever offered in the approval pop-up of a full sync or a check; the level sent is `plexRatingToSend`'s (the Plex line as edited, else the note's converted rating as edited, else the offer). Ratings, playlists and music files' own tags and lyrics files are the only things the plugin writes outside the vault.
- Steam collections (`steamCollections` source) come from the Steam client's local cloud storage file (`userdata/<account id>/config/cloudstorage/cloud-storage-namespace-1.json`, parsed by `collectionsByGame`; read by `readSteamCollections` in `src/steam-local.ts` through Node's fs, desktop only, in `settings.steam.folder` or the usual places). Hidden and dynamic collections are left out. A game's collections can also set its status (`PropertyValues.collectionStatus`, pairs edited in the Steam library's "Status from Steam collections" setting, `parseCollectionStatus`; defaults `DEFAULT_COLLECTION_STATUS`, given to saved libraries through `defaultValues`): `sourceValue('status')` takes `collectionStatus`'s (first pair that applies, any case) over the playtime status; a pair with `untilStarted` (written "(until started)" in the setting; Right Now → planned, also set on saved pairs by `migrateOnce('collection-planned-until-started')`) is passed over once `gameStarted` (playtime, or the note's status anything but empty, not played or an until-started status), so a started game is never set back to planned; in full syncs with asking on, `planCollectionStatus` offers it (merged into the `update:` lines) even backwards and regardless of `updateStatus`, a refusal kept with `keep`; in checks it starts ticked; without asking (and in the background) only the usual forward-only rule applies. Collections are read when the library uses `steamCollections`, or `status` with pairs set. Writing statuses back to Steam collections is ruled out like collections. `MIRRORED_SOURCES` are updated on every sync (and in the background) whenever they can be read; where they can't (phones), the property is left alone. Writing collections back to Steam was ruled out (it needs the owner's login session and can wipe collections).
- The owner's rating scale (`RatingScale` 'stars', the "Your rating (💣 ⭐ 🩷)" source): one per Plex star, 💣 ⭐⭐ ⭐⭐⭐ ⭐⭐⭐⭐ 🩷, empty for none, in every library (`starEmoji`; Plex's 0–10 is levels × 2). Notes written before it used 'emoji' (💣 ⭐ ⭐⭐ ⭐⭐⭐ 🩷 for Plex's pairs) or, for music, 'plain' (⭐ to ⭐⭐⭐⭐⭐); `noteStars` reads a note in the scale `noteScale` gives it, the old one until `settings.ratingsReviewed` has its rating key. Every pop-up for a note not yet reviewed (syncs with asking on, checks, "Use an existing note") offers its rating in the star scale (`planRescale`/`planRescaleOf`, `rescaleLines`, `applyRescale`; editable); answering marks it reviewed either way. Book notes (keyed `book:<path>`, old scale 'emoji', any property named like a library's emoji rating property) get it in the check, found on Open Library or not. Notes the plugin creates are reviewed from the start.
- Music file tags (source `fileTag`, the tag's name in `PropertyMapping.text`, passed to `sourceValue` everywhere): `prepare` reads each track's file (the listing's `Media[0].Part[0].file`; Obsidian runs on the Plex machine) with `readFileTags` (`src/music-files.ts`, desktop only, Node fs, only the ID3 tag at the start), parsed by the pure, tested `readId3`/`tagValue` (`src/id3.ts`: ID3v2.2–2.4, standard frames by ID, the owner's own TXXX tags by name, friendly names like Tempo), into `PlexItem.fileTags`; only for music libraries using the source, and not for 'playCounts' runs, recommendations or explain. Files are only ever written from the approval pop-up: in full syncs with asking on and in checks (only the properties chosen), `planFileWrites` offers, unticked (`file:<name>` lines, labelled "<name> in the music file" / "in the lyrics file"), to write a note's value that differs from the file's to an own tag (TXXX) the file already has, with one value, or to the existing lyrics file (never made); a refusal is kept with `keep` (`<key>|file:<name>`), and a ticked one drops the same property's `fix:` line (the note keeps its value, taking the pop-up's edit). `applyFileWrites` calls `writeOwnTag` (re-reads the tag and writes nothing if it changed since `prepare` read it; the pure, tested `setOwnTag` rewrites the frame in its own encoding, moving later frames into or out of the padding so the tag and file keep their size; only ID3v2.3/2.4, not unsynchronised, no footer, one such frame, enough padding; only the changed bytes are written, in the same file, then read back) or `writeLyrics` (same check; the same file rewritten in its own encoding and line endings, `textForm`/`encodeTextFile`); refusals go in `result.failed`, writes in `result.sentToFiles`. Nothing else in a music file is ever written. Lyrics (source `lyricsFile`, `PlexItem.lyrics`) come the same way from the text file beside the music file (`readLyrics`: same name with .txt or .lrc, decoded by `decodeText`, Windows line endings made plain, otherwise exactly as written).
- Songs' play counts go in Progress (`viewCount`; in `DEFAULT_MUSIC_PROPERTIES`, added to saved music libraries by `migrateOnce('music-progress')`); a song's count is never lowered or offered lower (`planUpdates`, `checkValue`, `planCountChoices`; it may be Last.fm's or count plays neither source knows).
